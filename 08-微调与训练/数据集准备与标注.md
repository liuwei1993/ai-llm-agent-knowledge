# 数据集准备与标注  
> **面向工业级大模型微调的高质量数据工程实践指南**  
> *适用于LLM微调（SFT、DPO、RLHF）、多模态模型训练及垂直领域Agent构建*

---

## 1. 核心概念与原理

### 1.1 什么是“数据集准备与标注”？  
在大语言模型（LLM）微调语境下，**数据集准备与标注**并非传统CV/NLP中的简单打标任务，而是一套**端到端的数据工程范式**，其目标是：  
✅ 将原始、异构、低信噪比的文本/多模态素材，转化为**结构化、语义对齐、分布可控、可复现、可审计**的监督信号；  
✅ 为下游微调任务（如指令遵循、事实一致性、安全对齐、工具调用）提供**高质量、高信息密度、低偏差**的训练样本。

### 1.2 设计思想：从“数据即原料”到“数据即代码”  
- **数据即代码（Data-as-Code）**：标注规范（Schema）、清洗逻辑、采样策略应版本化（Git）、可测试（pytest）、可回滚。  
- **分层抽象（Layered Abstraction）**：  
  - **Raw Layer**：原始日志、网页快照、客服对话录音转文本（含ASR置信度）；  
  - **Curated Layer**：去重、脱敏、格式归一化后的中间数据集；  
  - **Task-Specific Layer**：按微调目标构造的最终样本（如 `{"instruction": "...", "input": "...", "output": "...", "metadata": {...}}`）。  
- **人机协同闭环（Human-in-the-Loop + LLM-as-Labeler）**：标注员不直接写答案，而是**校验/修正LLM初筛结果**（如：标注员仅需点击“正确/错误/需重写”），效率提升3–5×（参考Anthropic 2023 Red Teaming Report）。

### 1.3 为什么它比模型架构更重要？  
> **“Garbage in, garbage out” 在LLM时代被放大100倍**：  
> - 一个10万条的SFT数据集，若含15%的事实性错误或风格漂移，微调后模型在OOD场景下幻觉率上升47%（LMSYS Org 2024基准测试）；  
> - 同一模型在Alpaca vs. UltraFeedback数据上微调，胜率差距达32.6%（Arena Hard），主因是标注质量而非数据量。

### 2.2 关键技术模块详解

#### ▶ 自动预标注（LLM-as-Labeler）
- **原理**：使用强基座模型（如Qwen2-72B、Claude-3-Opus）对原始文本生成候选标注，再由轻量模型（如Phi-3-mini）做一致性打分。  
- **算法**：采用**Self-Consistency Voting + Uncertainty-Aware Filtering**：  
  ```python
  # 伪代码：对同一query生成5个回答，取3票以上一致的答案
  candidates = [llm(prompt) for _ in range(5)]
  final_label = majority_vote(candidates) 
  if entropy(candidates) > 0.8:  # 高不确定性 → 进入人工队列
      send_to_human_review(prompt)
  ```

#### ▶ 质量验证（Quality Assurance Pipeline）
| 检查项         | 方法                                                                 | 工具示例                     |
|----------------|----------------------------------------------------------------------|------------------------------|
| **事实性**     | 使用检索增强验证（RAG）比对维基/知识库，检测实体矛盾                 | `llama-index + BM25 + SPARQL` |
| **安全性**     | 多模型ensemble检测（Llama-Guard-3 + Microsoft-ProtectiveAI）        | HuggingFace `transformers`   |
| **多样性**     | 计算样本间BERTScore相似度矩阵，剔除>0.95的簇                        | `bert-score==0.3.13`         |
| **分布偏移**   | 对比训练集vs.线上流量的n-gram KL散度，触发重采样                     | `scipy.stats.entropy`        |

#### ▶ 标注Schema设计原则
- **强制字段**：`id`, `source`, `timestamp`, `annotator_id`, `confidence_score`  
- **任务相关字段**（以SFT为例）：  
  ```json
  {
    "instruction": "将以下SQL查询转换为自然语言描述",
    "input": "SELECT name FROM users WHERE age > 30;",
    "output": "查询所有年龄大于30岁的用户姓名。",
    "reference_answer": ["列出30岁以上用户的姓名"], // 多标准答案
    "difficulty_level": "medium",
    "domain_tags": ["database", "sql"],
    "safety_flags": {"toxicity": 0.0, "bias": 0.12}
  }
  ```

### 示例1：构建可版本化的SFT数据集（支持Git-LFS）
```python
# data_pipeline/sft_builder.py
from datasets import Dataset, DatasetDict
import pandas as pd
import json
from pathlib import Path

class SFTDatasetBuilder:
    def __init__(self, base_dir: str):
        self.base_dir = Path(base_dir)
        self.raw_dir = self.base_dir / "raw"
        self.curated_dir = self.base_dir / "curated"
        
    def load_raw_data(self) -> pd.DataFrame:
        """加载原始JSONL（含ASR置信度、来源URL、时间戳）"""
        df = pd.read_json(self.raw_dir / "web_scraped.jsonl", lines=True)
        # 过滤低置信度ASR（<0.75）和广告文本
        return df[df["asr_confidence"] >= 0.75].drop_duplicates("text")
    
    def apply_curations(self, df: pd.DataFrame) -> pd.DataFrame:
        """标准化+去噪"""
        df["text"] = df["text"].str.replace(r"\s+", " ", regex=True).str.strip()
        df = df[df["text"].str.len() > 20]  # 剔除过短文本
        return df
    
    def generate_sft_samples(self, df: pd.DataFrame) -> Dataset:
        """构造SFT样本（使用预训练的prompt模板）"""
        from jinja2 import Template
        template = Template(
            "### Instruction:\n{{ instruction }}\n\n### Input:\n{{ input }}\n\n### Response:\n{{ output }}"
        )
        
        samples = []
        for _, row in df.iterrows():
            # 用规则引擎生成instruction-input-output三元组
            if "SELECT" in row["text"]:
                inst = "将SQL查询转换为自然语言描述"
                inp = row["text"]
                out = self._sql_to_natural_language(inp)  # 调用LLM预标注
            else:
                inst = "总结以下技术文档要点"
                inp = row["text"][:2000]
                out = self._summarize_with_llm(inp)
            
            samples.append({
                "instruction": inst,
                "input": inp,
                "output": out,
                "source": row["url"],
                "timestamp": row["timestamp"],
                "annotator_id": "auto-qwen2-72b-v1",
                "confidence_score": 0.92
            })
        
        return Dataset.from_list(samples)
    
    def save_versioned_dataset(self, dataset: Dataset, version: str):
        """保存为Arrow格式（支持增量更新）"""
        ds_path = self.curated_dir / f"sft_v{version}"
        dataset.save_to_disk(str(ds_path))
        # 生成版本摘要
        with open(ds_path / "VERSION.json", "w") as f:
            json.dump({
                "version": version,
                "size": len(dataset),
                "date": pd.Timestamp.now().isoformat(),
                "schema": list(dataset.features.keys())
            }, f, indent=2)

# 使用示例
builder = SFTDatasetBuilder("./data")
raw_df = builder.load_raw_data()
curated_df = builder.apply_curations(raw_df)
sft_ds = builder.generate_sft_samples(curated_df)
builder.save_versioned_dataset(sft_ds, "20240520")
```

### 示例2：自动化质量验证流水线
```python
# qa_pipeline/validator.py
from bert_score import score
from transformers import pipeline
import numpy as np

class QualityValidator:
    def __init__(self):
        self.safety_checker = pipeline(
            "text-classification", 
            model="meta-llama/LlamaGuard-3-8B",
            device="cuda:0"
        )
    
    def validate_factuality(self, sample: dict, knowledge_base: list) -> bool:
        """基于检索的事实性验证"""
        from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
        # 构建向量库（此处简化）
        index = VectorStoreIndex.from_documents(knowledge_base)
        query_engine = index.as_query_engine()
        response = query_engine.query(f"根据知识库，'{sample['output']}'是否正确？")
        return "yes" in str(response).lower()
    
    def validate_diversity(self, dataset: Dataset, threshold: float = 0.95) -> bool:
        """计算样本间相似度矩阵"""
        cands = dataset["output"][:1000]  # 抽样检测
        P, R, F1 = score(cands, cands, lang="zh", verbose=False)
        sim_matrix = F1.numpy()
        # 检测是否存在高相似簇
        np.fill_diagonal(sim_matrix, 0)
        return (sim_matrix.max() < threshold)

# 运行验证
validator = QualityValidator()
assert validator.validate_factuality(sft_ds[0], kb_docs), "Factuality check failed"
assert validator.validate_diversity(sft_ds), "Diversity check failed"
```

## 5. 常见面试问题与参考答案

### Q1：如何设计一个支持多轮对话微调的数据集？与单轮SFT有何本质区别？  
**答**：  
- **核心区别**：单轮SFT建模 `P(y|x)`，而多轮对话需建模 `P(y_t | x, y_1..y_{t-1})`，要求数据包含**完整上下文窗口**和**角色状态跟踪**。  
- **Schema设计要点**：  
  ```json
  {
    "conversation_id": "conv_123",
    "turns": [
      {"role": "user", "content": "推荐Python学习路径", "timestamp": "2024-05-01T10:00:00Z"},
      {"role": "assistant", "content": "建议从《流畅的Python》开始...", "timestamp": "2024-05-01T10:00:12Z"},
      {"role": "user", "content": "有没有免费资源？", "timestamp": "2024-05-01T10:01:05Z"},
      {"role": "assistant", "content": "推荐freeCodeCamp的Python课程...", "timestamp": "2024-05-01T10:01:22Z"}
    ],
    "dialogue_state": {"topic": "python_learning", "user_knowledge_level": "beginner"},
    "grounding_sources": ["freeCodeCamp.org", "realpython.com"]
  }
  ```  
- **陷阱规避**：避免截断历史（必须保留至少3轮上下文），且需标注**隐式状态变更**（如用户说“算了”，需标记 `intent_shift: abandon`）。

### Q2：当标注预算有限时，如何科学分配？优先标注哪些样本？  
**答**：  
采用**Uncertainty Sampling + Difficulty-Aware Prioritization**：  
1. 用当前模型对全量数据预测，计算熵值（Entropy）和预测置信度；  
2. 选取**高熵+低置信度**样本（模型最不确定的）；  
3. 结合业务规则加权：如金融场景中，含“收益率”“风险等级”的句子权重×3；  
4. **实证结论**（Google 2023）：该策略下，用30%标注预算即可达到92%全量标注效果。

### Q3：如何检测并消除标注员主观偏差？  
**答**：  
- **方法论**：  
  - **Inter-Annotator Agreement (IAA)**：计算Fleiss’ Kappa（多标注员）或Cohen’s Kappa（双标注员），阈值≥0.75；  
  - **Bias Audit Dashboard**：统计各标注员对“性别代词”“地域表述”的偏好比例，自动触发再培训；  
- **技术实现**：  
  ```python
  # 使用statsmodels计算Kappa
  from statsmodels.stats.inter_rater import fleiss_kappa
  # matrix[i][j] = number of raters who assigned category j to item i
  kappa = fleiss_kappa(matrix, method='fleiss')
  ```

### Q4：标注过程中发现大量原始数据存在系统性错误（如ASR将“神经网络”识别为“神精网络”），怎么办？  
**答**：  
这是**数据管道缺陷**，必须升级至**根因修复**：  
1. 立即冻结该ASR模型版本的数据摄入；  
2. 构建纠错规则库（如正则 `r"神精网络" → "神经网络"`），注入预处理流水线；  
3. 对已标注数据进行**影响范围分析**（Impact Analysis）：  
   ```sql
   SELECT COUNT(*) FROM sft_samples 
   WHERE output LIKE '%神精网络%' OR input LIKE '%神精网络%';
   ```  
4. **长期方案**：将ASR模块替换为**领域适配版Whisper-large-v3**（在医疗/法律语料上finetune）。

### Q5：如何保证不同批次标注数据的分布一致性？  
**答**：  
- **技术手段**：  
  - **Distribution Drift Detection**：每批次计算TF-IDF特征的Wasserstein距离，>0.15触发告警；  
  - **Stratified Sampling**：按`domain_tags`、`length_bin`、`sentiment_polarity`分层抽样，确保各层占比恒定；  
- **流程保障**：  
  - 发布新批次前，运行`diff`命令对比`VERSION.json`中的`schema_hash`和`distribution_stats`；  
  - 强制要求标注负责人签署《数据一致性承诺书》（含法律效力条款）。

## 6. 优缺点对比

| 方案                | 优点                                      | 缺点                                        | 适用场景                     |
|---------------------|-------------------------------------------|---------------------------------------------|----------------------------|
| **纯人工标注**       | 质量最高，可控性强                          | 成本极高（$20–50/条），周期长（月级）          | 安全关键场景（医疗诊断、金融风控） |
| **LLM预标注+人工审核** | 效率提升3–5×，成本降至$3–8/条，支持快速迭代     | 依赖基座模型能力，需强QA机制防止错误传播         | 通用SFT、RLHF初始数据构建       |
| **众包平台（如Scale）** | 弹性扩展，支持全球标注员                       | 数据主权风险，质量波动大，需定制质检规则          | 初创公司快速验证阶段             |
| **合成数据（Synthetic Data）** | 100%可控，无限生成，规避隐私问题                 | 语义真实性弱，易导致模型过拟合合成模式，需混合真实数据 | 法律/教育等低风险垂域           |

> 💡 **行业共识**：头部企业采用**混合模式**——核心指令数据（20%）人工精标，长尾泛化数据（80%）采用LLM预标注+强化QA。

| 技术                | 关系说明                                                                 |
|---------------------|--------------------------------------------------------------------------|

## 8. 踩坑经验与注意事项

### ⚠️ 致命陷阱（亲历案例）
- **陷阱1：忽略时序一致性**  
  > 某电商客服对话数据集中，用户问“我的订单12345发货了吗？”，标注员填了“已发货”，但实际物流系统显示“待揽收”。  
  > **解法**：所有标注必须绑定**数据快照时间戳**，并与业务系统日志对齐。

- **陷阱2：Schema演进未做向后兼容**  
  > 新增`reasoning_trace`字段后，旧版训练脚本因`dataset["reasoning_trace"]`报KeyError崩溃。  
  > **解法**：强制使用`dataset.features.get("reasoning_trace", None)`，并在`VERSION.json`中记录breaking change。

- **陷阱3：未隔离训练/验证/测试集的来源**  
  > 测试集来自2024年3月爬虫，训练集含2024年4月数据 → 模型在测试集上虚假繁荣（数据泄露）。  
  > **解法**：按**时间切片**划分，并用`pandas.Grouper(key="timestamp", freq="M")`确保无交叉。

### ✅ 必做事项清单
- [ ] 所有原始数据存入**不可变存储**（如AWS S3 + Versioning + Object Lock）  
- [ ] 标注平台强制开启**操作审计日志**（谁、何时、修改了哪条样本）  
- [ ] 每次发布新数据集，自动生成**数据卡（Data Card）**（含统计摘要、偏差分析、使用限制）  
- [ ] 在训练脚本中加入`assert len(dataset) > 0` 和 `assert dataset.features == EXPECTED_SCHEMA`
